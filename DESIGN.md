## Overview

Marginalia is the frontend for a local, single-user Retrieval-Augmented
Generation pipeline (see `PRODUCT.md`). The visual world — palette, type,
and the Reading Room's signature layout — was adopted wholesale from a
complete reference implementation the user supplied (not generated by a
concept round): a warm, archival paper world evoking a scholarly reading
room, where a cited answer and its evidence are never allowed to separate.

Light only, by deliberate decision — there is no dark variant. The product
is used at a desk, under steady light, reading long-form prose; the paper
metaphor doesn't have a night mode.

## Colors

60/30/10 archival discipline: `paper` is the dominant canvas (60%),
`parchment`/`stone` are structural surfaces — rails, panels, ledgers (30%),
and `accent` (oxblood) is the entire interactive/emphasis budget (10%) —
citation numerals, active states, primary buttons, rule weight on focus.
Never introduce a second saturated color; a status needs a role (ready,
danger) gets exactly one each, both desaturated enough to read as
structure rather than decoration.

Ink is a three-step hierarchy, not a single color with opacity: `ink`
(headings, primary prose), `ink-secondary` (supporting text, metadata
lines), `ink-muted` (timestamps, folio numbers, disabled/dormant state).
Never fake a lighter ink with opacity on `ink` — use the named step.

## Typography

Three workhorse families, each with exactly one job:

- **Newsreader** (serif) — all prose: headings, project/document titles,
  chat questions and answers, verbatim quotes. Never used for UI chrome.
- **Plus Jakarta Sans** (sans) — all interactive chrome: buttons, labels,
  form inputs, nav. Never used for prose or data.
- **JetBrains Mono** (mono, tabular figures) — anything that is data, not
  prose: dates, folio numbers (`No. 3`), document formats, section paths,
  counts, percentages. Always `tabular-nums` on numeric mono text.

Body sets at 15px-equivalent (the app's root `font-size: 18px` scales
everything up proportionally from the 16px browser default — a deliberate
accessibility choice, not part of this design's type scale). No display
face; headings scale by size and weight within Newsreader itself.

## Layout

A persistent top bar (`Shell.tsx`) in three zones — brand (links home) /
project-scoped tabs (only once a project is open: "Project Corpus (N)",
"Reading Room (Chat)") / nothing else — sits above every screen, 60px
tall, hairline rule beneath.

Most screens are a centered single column (max-width 960–1140px per
screen) with a breadcrumb back-link, a hairline-ruled header, and a
divided list below. The Reading Room (`ChatScreen.tsx`) is the exception:
a 3-column workbench (`lg:grid-cols-12`, 3/6/3 split) — chapter rail,
reading stream, Marginalia Passage Inspector — each independently
scrollable, collapsing to a stacked single column below `lg`.

No max-width cap on the Reading Room itself; it uses the full width Shell
leaves it. Reading measure is enforced per-column instead (68ch on the
stream's prose).

## Elevation & Depth

Flat. No shadows anywhere in this system — depth comes from the three-tier
background scale (paper/parchment/stone) and hairline rules
(`rule`/`rule-strong`), never from `box-shadow`. An active/selected state
is a background-color or border-color change, never a lifted shadow.

## Shapes

`rounded-md` (6px) is the default for panels, buttons, inputs, and
document ledger progress bars (as `rounded-full`). `rounded-sm` (2px) for
small interactive chips (the Lookup/Survey segmented toggle, the
cited/uncited filter toggle, citation jump buttons). No large radii, no
pill-shaped buttons except the inline citation marker badge, which is
`rounded-full` specifically because it stands in for a circled reference
numeral.

## Components

- **Citation marker** — an inline `<sup><button>` pill in prose text:
  bordered, tinted (`accent/10` background, `accent/50` border), inverts
  to solid `accent` fill with `paper` text on hover/focus. Clicking one
  opens that source in the Marginalia Passage Inspector.
- **Retrieved-passages ledger** — a `parchment` box prefacing every reply,
  listing every retrieved source (not just cited ones — a deliberate
  product invariant, see `CLAUDE.md`), with an All/Cited Only segmented
  filter. Cited rows are full-ink and mono-numbered in `accent`; uncited
  rows are `ink-muted` italic with "(retrieved, not cited)" spelled out.
  A summary-derived citation is always prefixed "(summary)" — never
  rendered identically to a real passage (`CLAUDE.md` invariant 6).
- **Marginalia Passage Inspector** — the signature component: a persistent
  right-hand column showing the full text of whichever citation is
  selected, labelled "Verbatim Document Excerpt" or, for a summary,
  "Summary" (never the former for the latter). Quoted text sits in a
  `border-l-2 border-l-accent` blockquote — the one place this system
  uses a colored side border, intentionally, as the reference's named
  "verbatim-quote" treatment.
- **Chapter rail row** — a flat list item with a 3px left border that
  turns `accent` when active; no card, no shadow. A hover-revealed
  "Remove" link soft-deletes; a collapsible "Deleted (N)" drawer at the
  rail's foot holds restorable chapters.
- **Document ledger row** — title (serif, links to structure review),
  format/status/summary-status metadata line in mono, a `stone`-track
  `accent`-fill progress bar for section summarization, and action
  buttons (Generate summary, Re-index, Delete…, Remove). A document delete
  requires typing its exact title to confirm — the one irreversible
  action in the app with no soft-delete equivalent.
- **Buttons** — primary (`accent` fill, `paper` text) for the one
  consequential action per view (Create, Attach, Chat with Corpus, Send);
  secondary (`parchment`/`paper` fill, `rule-strong` border, `ink` text)
  for everything else; danger text-only (`danger` color, no fill until
  hover) for destructive actions.

## Do's and Don'ts

- Do keep the ink hierarchy to its three named steps; don't invent a
  fourth with opacity.
- Do use mono exclusively for dates, counts, paths, and other structured
  data; don't use it as a "technical-looking" costume on prose.
- Do label a summary-derived citation as a summary everywhere it appears
  (ledger, inspector); don't let one render identically to a real passage.
- Do keep the accent color to its 10% budget (citations, active states,
  primary actions); don't introduce a second saturated color for variety.
- Don't add a dark variant — this world is pinned light-only.
- Don't add shadows, rounded chat bubbles, or card containers; depth and
  grouping come from the paper/parchment/stone scale and hairline rules.
